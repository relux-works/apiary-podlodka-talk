# Проблема — *две недоверяющие стороны*

<DiagV4DSwarm reveal />

<p v-click class="lead orange">Граница должна держаться с обеих сторон, и держать её должно ядро ОС, а не инструкция.</p>

<!--
[Иван] Мы не можем доверять чужому агенту: это агентский цикл, он может написать любой код, сломать и заразить нашу среду. Это не теория. Летом 2026 у OpenAI агенты должны были быть изолированы, но граница не держалась: общий кэш пакетов стал каналом, около 1 200 агентов завели несанкционированную доску сообщений, и около 700 из них атаковали Hugging Face.

# Рабочее место *внешнего агента*

<DiagV4DWorkplace reveal />

<p v-click class="lead lime">Граница с двух сторон: у нас — свой пользователь ОС, у донора — ни одного локального инструмента.</p>

<!--
[Иван] Решаем с двух сторон. У нас — проверенные примитивы ОС: на нашей машине для чужого агента заводится рабочее место, отдельный пользователь со своим домом и правами. Песочница — само ядро, как в Android, где каждое приложение — свой пользователь; Docker не нужен. Наружу у этого пользователя нет ничего, даже loopback: только объявленные сокеты платформы, и запускать он может только разрешённые команды, без сборок и тестов. Донор входит туда по SSH своим ключом, после рукопожатия.

Модель думает у донора, на его подписке, а руки — у нас. У его агента выключены свои инструменты, остаётся один мост в нашу среду, где заранее подготовлен проект. Задачи и результаты ходят подписанными письмами через мост и ящик, а код уходит только выгрузкой после раунда: импорт на доску, ревью у нас, подписанное приземление. Читается он как данные. Донор видит, что агент делает именно те задачи, под которые он отдал время. А наша машина к донору не подключается и команд туда не шлёт. Ключ нашего хоста мост донора сверяет при каждом подключении, а ключ донора лежит у нас вне дома его пользователя, и инструмент оболочки не допишет туда свой. Пропала связь — мост донора ставит работу на паузу.

[Для себя] Защита донора по вариантам (Curator CIP-0008/0009, ревизия 3): A — запертый режим без локальных инструментов, первая веха; B — две личности ОС у донора; C — песочница ядра. «Физически не может ничего сделать на машине донора» верно для B и C; для A — «агенту не дают никаких инструментов на машине донора». Пейпер: книга Swarma v0.9 есть, опубликованного пейпера нет; Алексей (12.10): про реализацию — подробно, только если пейпер выйдет до доклада.

Источники: контракт trust-and-isolation v1.3 §1 п. 3 («The kernel is the sandbox», решено), §5 (пользователь ОС на агента, файрвол по UID), §7 (рабочее место: authorized_keys с restrict и принудительной командой исполнителя; соединение только к нашему хосту и только для инструментов; к донору ни соединений, ни команд — решено); curator-spec PR #134, CIP-0008 и CIP-0009 ревизии 3 (поза lockdown, одно реле MCP с узким набором инструментов: bash, чтение и запись файлов, патч, почта; варианты A, B, C; CIP-0009 D5 — единственное соединение — SSH от донора к нам); wiki book/swarma/ru/11 («модель думает у донора, руки — у нас»; «Ключ нашего хоста мост донора сверяет при каждом подключении»; файл разрешённых ключей принадлежит root и лежит вне дома пользователя; при потере связи мост донора ставит работу на паузу); ревью ivan-network-profiles 12.10 (проверенные примитивы ОС: пользователь на агента, файрвол по пользователю, песочница — на macOS и Linux); wiki session-host/architecture.ru.md §7.5 (Android: приложение — свой UID); разговор спикеров 12.10 («десятилетиями проверенные примитивы ядра», «один мета-тул… через мост», «полный observability», «двойная система ограничений»; канал в одну сторону из «Безопасности роя» — оставить). Сверено с ivan-curator 13.10 по принятому дизайну (TRU 6b3f983 §5, §7; N15 359365e; CIP-0009 D5a–D5c): ноль исходящих для рабочего места, прокси и аренды учётных данных у него нет, команды по списку разрешённых (R-EXEC), код — только через R-TRANSFER; веб у донора выключен по умолчанию, поиск — только у донора из доверенного круга по его выбору и на его стороне (CIP-0009 D5b); рабочее место — в недоверенном классе, пока оператор не принял донора в доверенный круг; донор входит через отдельный публичный хост присоединения, на нём нет ключа подписи допуска. Статус: решено, не построено.
