# Гайд: стиль «RWB tech» для Slidev

Корпоративный шаблон RWB для докладов (тёмный фон, карточки, фиолетовые плашки-выводы, лесенка квадратов, 3D-иконки на открывашках) — доведённый до консистентной системы: одна сетка, одна шкала кеглей, четыре роли цвета. Для сложных технических тем, где содержание важнее оформления.

Проверено на Slidev 52.19.1: `npm run theme:rwb-tech` открывает витрину, `npm run verify` проходит для дека на этой теме.

Комплект: `themes/rwb-tech/` — локальная тема Slidev (`slidev-theme-rwb-tech`), `themes/rwb-tech/example.md` — витрина всех раскладок и компонентов на слайдах доклада iOS Crew #18, где тема родилась. Подключение к деку, логотип и смена темы — в [`../README.md`](../README.md).

## 1. Канон в десяти правилах

1. **Одна композиция на слайд.** Заголовок сверху, содержимое, вывод плашкой внизу. Клики только раскрывают части композиции, не перестраивают её.
2. **Фон `#161616`, текст белый.** Фиолетовая заливка `#7F30E3` на всю страницу — только открывашки частей и финал.
3. **Карточки — основной блок.** Серая `#474747` — нейтральная; фиолетовая — «другая сторона» сравнения или главное; сирень / лайм / оранжевый — светлые заливки с тёмным текстом `#161616`. На слайде не больше двух акцентных заливок.
4. **Вывод — плашка.** Абзац `class="lead"` в рабочей раскладке становится фиолетовой плашкой и прижимается к низу; `lead lilac` — светлый вариант. С v6 (12.10) `lead orange` — новая проблема, `lead lime` — решение или итог: проблему подсвечиваем оранжевым, решение — лаймом. Всё внутри плашки одного цвета, выделения — жирным, не цветом.
5. **Заголовок 36 px, средний вес, второй смысловой отрезок — сиренью:** `# Так мы *делаем сегодня*`. Заголовки — утверждения или вопросы, без «не X, а Y».
6. **Логотип RWB на каждом слайде:** приглушённый в правом верхнем углу рабочих слайдов, белый на открывашках и финале; на титуле он внутри карточки конференции, на демо-бамперах его нет.
7. **Футер на каждом слайде:** название доклада слева, тег части и номер справа. Тег берётся из `tag:` во frontmatter.
8. **Пиксельный мотив — лесенка квадратов** модуля 69 px: открывашки, демо-бамперы, финал. Маленькие мотивы (`<PixelMotif>`) — только крестик / галочка у заголовка там, где они несут смысл.
9. **Минимальный кегль — 13 px** (подписи диаграмм, футер). Текст 17, карточки 16, крупные карточки 20, таблицы 16, код 15 (14 в `dense`), заголовок 36, открывашка 64, число-якорь 48.
10. **Не помещается — `class: dense` во frontmatter или два слайда,** а не мельче кегль. Проверка — `node .scripts/audit-overflow.mjs`.

## 2. Токены

CSS-переменные (`themes/rwb-tech/styles/base.css`):

| Роль | Переменная | Значение |
|---|---|---|
| фон | `--rwb-bg` | `#161616` |
| карточка | `--rwb-card` | `#474747` |
| карточка кода | `--rwb-card-dark` | `#2B2B2B` |
| фиолетовый · плашка, акцентная карточка, открывашка | `--rwb-purple` | `#7F30E3` |
| сирень · акцент заголовка, светлая заливка | `--rwb-lilac` | `#BF97F1` |
| лайм · готово, проверка, зелёная зона | `--rwb-lime` | `#94E330` |
| оранжевый · внимание, цена, красная зона | `--rwb-orange` | `#FE5F00` |
| текст | `--rwb-txt` | `#FFFFFF` |
| текст на светлых заливках | `--rwb-ink` | `#161616` |
| вторичный на фоне / на карточке | `--rwb-sec` / `--rwb-sec-card` | `#A2A7B0` / `#D2D5DA` |
| футер, подписи, номера | `--rwb-dim` | `#8E8E8E` |
| линейки на фоне / на карточке | `--rwb-rule` / `--rwb-rule-card` | `#383838` / `rgba(255,255,255,.16)` |
| радиус карточек и плашек | `--rwb-radius` | `12px` |

Старые имена (`--rwb-node`, `--rwb-code`, `--rwb-deep`) остаются алиасами.

Шрифты: **Inter** 400/500/600 (текст), **JetBrains Mono** (код, теги, числа в диаграммах). Тема подключает их через `fonts` в `themes/rwb-tech/package.json` → Google Fonts; для офлайн-показа положите woff2 в `public/fonts` и добавьте `@font-face` в `styles/base.css`.

Сетка канваса 980×552: поля 36 px, заголовок от 30 px, содержимое до 494 px, футер на 507–522 px, логотип в правом верхнем углу высотой 26 px.

## 3. Раскладки

Раскладка задаётся во frontmatter слайда: `layout: …`. Остальные ключи — свойства раскладки.

| layout | Свойства | Слоты | Для чего |
|---|---|---|---|
| `cover` | `image` (файл из `public/`, на весь слайд), `event`, `who`, `role`, `contacts`; для нескольких спикеров — `speakers: [{ name, role, logo }]` колонками (компания в `role` отдельной строкой через `\n` в двойных кавычках; `logo: { src, alt, height }` — логотип компании слева от имени) и `about` — строка о проекте | default | титул: карточка конференции или текстовый вариант; логотип на текстовом — внизу слева |
| `section` | `num`, `sub`, `icon` (`server` · `cubes` · `computer` · `notepad`) | default = заголовок | открывашка части: фиолетовый фон, лесенка, 3D-иконка |
| `default` | `tag`, `source` | default | рабочий слайд: колонка «заголовок → содержимое → плашка» |
| `two-cols` | `tag`, `source`, `left-tone`, `right-tone` | `::title::`, default (левая карточка), `::right::` (правая), `::bottom::` | сравнение: серая карточка против фиолетовой |
| `code-side` | `tag`, `source` | `::title::`, default (код), `::side::` | код 2/3 ширины + фиолетовая карточка с пояснением |
| `demo` | `tag`, `num` («Демо 1»), `live` | default = заголовок и подзаголовок | бампер перед демо; `live: true` — демо внутри слайда: метка и заголовок 28 px в одну строку, под ними визуализация 908 × 414, из квадратов только угловой оранжевый (docs/demos.md в деке) |
| `statement` | `tag`, `after` | default | одно утверждение крупно |
| `end` | `who`, `contacts`, `qrs` (массив подписей) | default | финал на фиолетовом: спасибо, места под QR, контакты |

Именованные слоты в Markdown — через маркеры `::title::`, `::right::`, `::side::`, `::bottom::`; содержимое до первого маркера или после `::default::` идёт в основной слот. `class: dense` во frontmatter уплотняет карточки и код. Все примеры — в `themes/rwb-tech/example.md`.

## 4. Карточки и компоненты

Разметка карточек — обычный HTML в Markdown (внутри HTML-блока markdown не парсится, поэтому `<strong>`, а не `**`):

```html
<div class="cards cols-2 grow">
<div v-click="1" class="card num" data-num="01"><h2>Заголовок</h2><p>Текст</p></div>
<div v-click="2" class="card purple">…</div>
</div>
```

| Класс | Назначение |
|---|---|
| `.cards.cols-2/3/4` | сетка карточек с зазором 16 px; `grow` растягивает до плашки или футера |
| `.card` | серая карточка; `h2` внутри — сиреневый заголовок |
| `.card.purple` · `.lilac` · `.lime` · `.orange` | заливки; светлые — с тёмным текстом |
| `.card.big` | крупный текст 20 px для списка «пункт = карточка» |
| `.card.num` + `data-num="01"` | номер в правом нижнем углу |
| `p.lead` · `p.lead.lilac` · `p.lead.orange` · `p.lead.lime` | плашка-вывод внизу рабочей раскладки; оранжевая — новая проблема, лаймовая — решение или итог |
| `p.note` | подпись под плашкой, 14 px приглушённым |
| `.timeline` | сетка «год — событие» с линейками, год в классе `y` |

Компоненты регистрируются автоматически из `themes/rwb-tech/components/`:

| Компонент | Использование | Назначение |
|---|---|---|
| `<BigNum value="$4.57" caption="…" tone="neutral" size="xl" />` | внутри `.cards` | число-якорь в карточке: фиолетовая по умолчанию, `neutral` — серая с сиреневым числом, `xl` — число на всю карточку |
| `<Stack reveal :layers="[['Термин','пояснение','lilac'], …]" />` | на фоне или в карточке | строки «термин — пояснение» с линейками; третий элемент — цвет термина |
| `<Boxes :items="['a','b']" :arrows="false" color="lime" :colors="['orange','lilac']" />` | ряд плашек | шаги, категории; `color` — общая заливка, `colors` — по плашке |
| `<PixelMotif pattern="cross|tick" :cell="10" :gap="2" />` | у заголовка | маленький мотив там, где он несёт смысл |
| `<Squares set="section|demo|demo-live|end|statement" />` | внутри раскладок | лесенка квадратов; в свои слайды не ставить |
| `<SourceNote text="…" />` | через `source:` | источник строкой над футером |
| `<Ph>⟨…⟩</Ph>` | внутри текста | плейсхолдер / [VERIFY], янтарный mono |
| `<RwbChrome>` | внутри раскладок | логотип и футер; раскладки ставят его сами |

Таблицы — обычный Markdown: тонкие линейки, сиреневая шапка, 16 px; внутри карточки шапка становится заголовком карточки. Код — блоки ` ```bash {7,8} `, тёмная карточка `#2B2B2B`, подсветка: ключевые слова — сирень, строки и числа — оранжевый (`themes/rwb-tech/setup/shiki.ts`).

Диаграммы — inline SVG без обводок: узлы `rect` с классами `n` (серый), `n-lilac`, `n-lime`, `n-orange`, `n-purple`, `n-wait` (пунктир); текст — `t-ink` (тёмный на светлой заливке), `t-sec`, `t-dim`, `t-lilac`, `t-lime`, `t-orange`, `t-big` (15 px sans), `t-lab` (16 px sans), `t-cap` (14 px sans), `t-head` (шапка группы); рёбра — `e`, `e-lime`, маркеры — `m`, `m-lime`. Координаты фиксируем руками; атрибуты `font-size`/`fill` на `<text>` не ставить — UnoCSS attributify читает `font-size="13"` как утилиту.

## 5. Что менять и чего не трогать при работе со слайдами

- Заметки спикера — HTML-комментарий в конце слайда, это абзацы текста доклада. Не сокращать.
- Порядок клика сохраняем: `v-click="n"` на карточках и пунктах, `<v-clicks>` не оборачивает карточки.
- Колонки сравнения — `two-cols`: левая всегда серая, правая фиолетовая; цветные `span` в заголовках карточек наследуют цвет карточки.
- Открывашки частей — `section` с иконкой из четырёх; новых 3D-иконок не добавляем.
- Титул — карточка конференции (`image:`); текстовый титул темы — запасной вариант.
- Финал: QR-плейсхолдеры остаются пунктирными, пока нет настоящих кодов.

## 6. Запуск и экспорт

```bash
npm install
npm run theme:rwb-tech                # витрина темы, http://localhost:3030
npm run dev                      # дек из slides/slides.md
npm run verify                   # lint → офлайн-сборка → аудит всех слайдов
npm run export                   # PDF в .temp/export/
```

Экспорт в PDF идёт с реальными шрифтами; в PowerPoint-экспорт каждый слайд попадает картинкой — редактируемым он не будет, это ограничение Slidev.

## 7. Чеклист перед показом

- на каждом слайде один анкер и не больше двух акцентных заливок;
- заголовок с сиреневым акцентом на рабочих слайдах; открывашки, демо и финал — без него;
- ни одного текста меньше 13 px; код ≤ 14 строк; таблицы ≤ 6 строк;
- плашка-вывод прижата к низу, ничего не заходит под футер (`audit-overflow.mjs` — ноль переполнений);
- все `<Ph>` заменены реальными значениями или слайд помечен как черновой;
- у каждого числа и чужого факта есть источник — в заметках спикера и в `open-questions.md`; строки «ФАКТ/ОЦЕНКА» на слайд в этой теме не ставим;
- экспорт в PDF открыт и пролистан: логотип и футер на каждой странице, переносы заголовков, шрифты.
